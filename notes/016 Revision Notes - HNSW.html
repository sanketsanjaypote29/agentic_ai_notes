HNSW - Hierarchical Navigable Small World

How vector databases find nearest neighbors in milliseconds across 10M+ vectors

HNSW is a graph-based algorithm for Approximate Nearest Neighbor (ANN) search. Given a large collection of high-dimensional vectors and a query vector, it finds the K most similar vectors in milliseconds - without scanning the entire dataset.

It works by building a multi-layer graph where upper layers act as express routes across the entire vector space, and the bottom layer holds every vector with dense local connections. A query starts at the top, navigates down layer by layer, and arrives at the exact neighbourhood of the answer - visiting only a tiny fraction of the index.

Published by Malkov & Yashunin in 2018, it became the default ANN index for almost every vector database because it combines high recall, low latency, and dynamic inserts without needing a training or clustering phase.

Where HNSW is used

Used as the default ANN index in Pinecone, Weaviate, Qdrant, pgvector, FAISS, Chroma, and Milvus.

The Problem: Brute Force is O(N)

Given 10 million vectors, each with 1536 dimensions, and a query vector Q - find the top-K most similar vectors.

Per single comparison: 1536 multiplications + 1535 additions ≈ 3071 ops

For 10M vectors: 10,000,000 × 3071 = 30.7 Billion operations

Brute Force Latency Estimates (1536-dim)

How fast is one operation?

A modern CPU core runs at ~3 GHz and with SIMD (AVX2) can do 8 float32 multiply-adds per cycle:

Throughput = 3 × 10⁹ cycles/s × 8 ops/cycle = ~24 billion ops/second

So 1 arithmetic op ≈ ~0.04 nanoseconds (with SIMD)
Without SIMD (scalar): 1 op ≈ ~0.33 ns (one per cycle at 3 GHz)

Deriving the 10M vector latency:
30 Billion ops ÷ 24 Billion ops/sec = ~1.25 seconds (SIMD best case)
30 Billion ops ÷ 3 Billion ops/sec = ~10 seconds (scalar worst case)

The 1–5 sec range in the table sits in between, accounting for memory bandwidth bottlenecks and cache misses.

The Hierarchy: Solving Local Optima with Layers

Upper layers have long-range express routes. Lower layers have dense local connections. We navigate top-down, zooming in.

Layer Structure - Exponentially Fewer Nodes Per Layer

Search enters at the top (L4, fewest nodes), greedily descends layer by layer, zooming in on the correct region before doing dense local search at L0.

How Layer Assignment Works - Exponential Random Draw

When inserting a new node, its maximum layer l is drawn randomly:

l=⌊−ln⁡(uniform(0,1))⋅mL⌋ where mL=1ln⁡M

A node assigned max layer = 3 exists in layers 3, 2, 1, 0 with separate neighbor lists in each.

Node A (max layer=3):
L3: A → {D, G}
L2: A → {B, D, F}
L1: A → {B, C, D, E}
L0: A → {B, C, D, E, I, J...}

This geometric distribution is not a design accident - it mirrors skip-list theory, ensuring expected O(log N) navigation depth.
