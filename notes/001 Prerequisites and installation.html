Why Poetry? And How to Install It

We use Poetry instead of pip. Here is exactly why — and how to get it running.

Why Not Just Use pip?

pip works fine for simple scripts. For any real project — especially AI projects with complex, interacting dependencies — pip creates problems that Poetry solves cleanly.

ProblemWith pipWith Poetry
Reproducible installs ✗ requirements.txt has no lock. Versions drift between machines and over time. ✓ poetry.lock pins every dependency to the exact version — forever reproducible.
Virtual environments ✗ You create, activate, and manage venvs manually every time. ✓ Poetry creates and manages a project venv automatically.
Dependency conflicts ✗ Conflicts are discovered at runtime, often with cryptic errors. ✓ Poetry's resolver catches conflicts at add-time before anything breaks.
Dev vs prod deps ✗ Requires managing multiple requirements-*.txt files manually. ✓ Built-in groups: [dev], [test] — clean, explicit separation.
Project metadata ✗ Spread across setup.py, setup.cfg, MANIFEST.in. ✓ Everything in one pyproject.toml — the modern Python standard.
Team collaboration ✗ "Works on my machine" is a real and common problem. ✓ Commit poetry.lock → every teammate gets an identical environment.

AI projects are especially dependency-fragile. LangChain, LangGraph, OpenAI SDK, Pydantic, and their transitive dependencies interact in complex ways. A single version mismatch can silently break tool calling or agent execution in ways that are very hard to debug. Poetry's lockfile eliminates this entire class of problem.

Install Poetry

Important
Do not install Poetry with pip install poetry inside a project. Install it globally using pipx or the official installer, so it stays isolated from the projects it manages.
macOS
Windows
Linux
bash macOS — via pipx (recommended) 
# Install pipx — the right tool for installing Python CLI apps globally

# Install Poetry

# Verify
poetry --version
# → Poetry (version 2.4.1)

# Configure Poetry to create the venv inside the project folder (makes IDE integration easier)
poetry config virtualenvs.in-project true

# The installer prints the PATH to add. It looks like:

poetry config virtualenvs.in-project true

poetry config virtualenvs.in-project true
Key Poetry Commands to Remember
poetry add <package> — add a dependency and update the lockfile
poetry install — install all deps from lockfile (reproducible)
poetry run python script.py — run a script inside the managed venv
poetry shell — activate the venv in your current terminal session

Create the Course Project & Virtual Environment

A Poetry project automatically sets up and manages the virtual environment for you.

Create a project folder for this course. We call it agentic-ai-course.

bash Create project with Poetry 
# Go to wherever you keep your projects
cd ~/projects          # macOS / Linux
# cd C:\Users\YourName\projects   ← Windows

# Create the project
poetry new agentic-ai-course
cd agentic-ai-course

# Open in your IDE
cursor .    # or: code .  for VS Code

Poetry creates this structure:

agentic-ai-course/
├── agentic_ai_course/ ← your Python package (we'll add scripts here)
│   └── __init__.py
├── tests/
│   └── __init__.py
├── pyproject.toml ← project config & dependencies
└── README.md

Understanding the Virtual Environment

Because you ran poetry config virtualenvs.in-project true in the previous step, Poetry will create the virtual environment inside the project folder as .venv/ the first time you run poetry install. This makes it easy for your IDE to detect it automatically.

bash Verify the virtual environment 
# Install the project (creates the .venv/ folder)
poetry install

# Check where the venv lives
poetry env info

# Activate the venv in your terminal (optional — poetry run works without this)
poetry shell

# You should now see (.venv) at the start of your prompt
# Verify Python inside the venv
python --version
# → Python 3.12.x  (from the venv, not your system Python)
IDE: Point it to the .venv
In Cursor or VS Code: press Cmd/Ctrl + Shift + P → "Python: Select Interpreter" → choose the interpreter inside .venv/. This gives you correct autocomplete and type checking for all installed packages.

If you accidentally push an API key to GitHub, rotate it immediately at platform.openai.com → API Keys.

Verify — Run the Demo Agent

If this script runs and prints a response, your entire environment is working.

Create the file agentic_ai_course/verify_setup.py and paste the code below. Running this script is your final confirmation that Python, Poetry, LangChain, and your OpenAI key are all wired up correctly.

python agentic_ai_course/verify_setup.py 
from dotenv import load_dotenv
from langchain.agents import create_agent
from langchain.tools import tool

# Load OPENAI_API_KEY from .env
load_dotenv()

# ── Define a simple tool ──────────────────────────────────────────────────────
# Tools are plain Python functions. The docstring is what the LLM reads —
# so write it clearly. The @tool decorator registers it with LangChain.

@tool
def add_numbers(a: float, b: float) -> str:
    """Add two numbers together and return the result."""
    return f"The sum of {a} and {b} is {a + b}"


@tool
def greet_user(name: str) -> str:
    """Greet a user by their name."""
    return f"Hello, {name}! Welcome to the Agentic AI System Design course."


# ── Create the agent ──────────────────────────────────────────────────────────
agent = create_agent(
    model="openai:gpt-4o-mini",       # using the fast, cheap model for verification
    tools=[add_numbers, greet_user],
    system_prompt="You are a helpful assistant. Use the tools available to you.",
)

# ── Run a test query ──────────────────────────────────────────────────────────
result = agent.invoke({
    "messages": [{
        "role": "user",
        "content": "Please greet me — my name is Alex. Also, what is 128 + 256?"
    }]
})

print("\n✅ Setup verified! Agent response:\n")
print(result["messages"][-1].content)

print("\n--- Message trace (shows the ReAct loop steps) ---")
for msg in result["messages"]:
    print(f"  [{type(msg).__name__:15s}] {str(msg.content)[:80]}")
bash Run the verification script 
poetry run python agentic_ai_course/verify_setup.py

You should see output like this:


✅ Setup verified! Agent response:

Hello, Alex! Welcome to the Agentic AI System Design course.
And the answer to 128 + 256 is 384.

--- Message trace (shows the ReAct loop steps) ---
[HumanMessage ] Please greet me — my name is Alex. Also, what is 128 + 256?
[AIMessage ] [tool_call: greet_user(name='Alex'), tool_call: add_numbers(a=128, b=256)]
[ToolMessage ] Hello, Alex! Welcome to the Agentic AI System Design course.
[ToolMessage ] The sum of 128 and 256 is 384
[AIMessage ] Hello, Alex! Welcome to the Agentic AI System Design course...
What You Are Seeing
Look at the message trace. The agent received your message, decided it needed both tools, called them, received the results, then wrote the final reply. This is the ReAct loop — Reason, Act, Observe, repeat — running live in your terminal. We will spend the entire course understanding, building, and optimising this pattern.

Common Errors & Fixes

ErrorLikely CauseFix
AuthenticationError Wrong or missing API key Check .env has OPENAI_API_KEY=sk-... and load_dotenv() is at the top of the script
ModuleNotFoundError: langchain Running with system Python instead of the Poetry venv Always use poetry run python or activate with poetry shell first
poetry: command not found Poetry not added to PATH Add ~/.local/bin (Linux/macOS) or %APPDATA%\Python\Scripts (Windows) to your PATH, then restart terminal
pydantic ValidationError Package version mismatch Run poetry update to sync everything to the latest compatible versions
Git push asks for password GitHub no longer accepts account passwords Use a Personal Access Token — see Step 4 in Section 07
